# STYX storefront polish audit — September 8, 2026

Follow-up: see [Variant images and quick entrances](VARIANT-IMAGES-AND-MOTION.md) for the broader animation pass and stricter finish filtering, which supersede the original gallery behavior below.

Scope: local homepage and shared navigation, desktop/mobile browser inspection, plus targeted source review. This is a focused UX audit, not a full checkout, SEO, or performance certification. “20% better” is a design brief, not a measured conversion or speed gain.

## Implemented

- Hero photograph sharpens from a small blur over one second; headline, description, and actions enter in sequence. The existing high-priority responsive image and preload remain in place.
- Fine gold corner marks and an eyebrow rule extend the existing editorial identity.
- Gold primary hero button and bone-colored secondary link improve visibility over the photograph. Actions can wrap on narrow screens.
- Desktop navigation enters gently; mega menus and their imagery reveal on opening and switching categories. Mobile menu rows enter in a short stagger.
- Collection tiles reveal once as they enter the viewport. Content is visible by default without JavaScript; already-visible content is never hidden on hydration. Keyboard focus also reveals pending tiles.
- A gold indeterminate line appears during router navigation, with a screen-reader loading status.
- Shared calls to action have a small hover lift and explicit focus rings. Transition properties are scoped instead of using `all`.
- Mobile menu close button now has an accessible name; its trigger reports expanded state.
- All new motion is opt-in to `prefers-reduced-motion: no-preference`. Reduced motion also removes existing animation delays; changing the preference reveals pending tiles immediately.
- Product gallery now suppresses duplicate catalog uploads of both the main image and alternate views. Verified the 13mm Cuban duplicate pairs had identical SHA-256 hashes at the same CDN rendition; four displayed images now become two. Curb keeps its two distinct views; Cable keeps its single view. Matching is intentionally limited to Shopify renditions and the verified `_N_keep` / `_N_shiny` UUID upload pattern, not arbitrary visual similarity.
- No additional runtime dependency.
